# Форматы, сохранение и ограничения

## Импорт Telegram Desktop

Поддержан **экспорт одного чата**, а не полный экспорт аккаунта с `chats.list`.
Архивы `.7z`/ZIP сначала распакуйте самостоятельно. Источники читаются, оригиналы не изменяются.
Папка выбирается через GUI или CLI; CLI также принимает файл. JSON имеет приоритет перед HTML.

### JSON

Корневой объект содержит `name` и массив `messages`. Сообщение имеет положительный уникальный `id`,
`date`, `type`, `from`/`from_id` или `actor`/`actor_id`, `text`.
`text` может быть строкой или массивом строк и объектов с `text`; видимое содержимое объединяется.
Адреса скрытых гиперссылок извлекаются из `href` внутри `text` и `text_entities`.
Поддержаны `photo`, `file`, `file_name`, основные `media_type`, `reply_to_message_id`, `poll` с `question`,
`closed`, `total_voters`, `answers[].text/voters`. Служебное действие отображается как отдельная запись.
Прочие поля игнорируются: реакции, координаты, контакты, сущности форматирования, todo и некоторые новые типы
не имеют специализированного представления. Обычный доступный текст сохраняется.
При отсутствии ID автора используется имя; одинаковые неизвестные имена в этом случае объединяются.

### HTML

Поддерживается структура Telegram Desktop `.history`, `.message[id]`, `.body`, `.from_name`, `.date[title]`,
`.text`, `.media_wrap`, `.media_poll`. Страницы `messages.html`, `messages2.html`, … объединяются по номеру,
а сообщения затем сортируются по дате и ID. Для joined-сообщений автор наследуется от предыдущего.
Даты `dd.MM.yyyy HH:mm:ss GMT+03:00` и `UTC+03:00` сохраняются как экспортированное местное время.
Служебные записи без времени привязываются к дате разделителя и отображаются с **00:00**: точного времени в HTML нет.
Отрицательные ID разделителей дней не считаются сообщениями.

HTML не содержит стабильных ID авторов: авторы определяются по имени. Двое с одинаковым именем могут объединиться.
Перенос строки `<br>` сохраняется; оформление bold/italic не воспроизводится, текст остаётся читаемым.
Локальные вложения извлекаются из ссылок в блоке медиа; web-ссылки — из HTTP/HTTPS href и текста.
Встроенные emoji-ассеты и реакции не превращаются в отдельные медиафайлы ленты.
Пропущенное при экспорте видео/аудио/документ сохраняет категорию, но показывает недоступность файла.
JavaScript, CSS и HTML-страница не выполняются в WebView: AngleSharp разбирает документ как данные.
Произвольный HTML сайта или экспорт другого клиента не обещаются.

В обоих форматах даты показываются как в экспорте, без пересчёта в текущую часовую зону компьютера.
Участники означают **авторов сохранённых сообщений**. Состав группы, молчащие участники,
удалённые сообщения и живые результаты голосований не могут быть восстановлены из отсутствующих данных.

## Ограничения объёма

До 128 МиБ на исходный файл/состояние и до 200 000 сообщений.
Для HTML дополнительно: до 500 страниц, до 256 МиБ суммарно.
Архив хранится в памяти; это учебное настольное приложение, без потоковой индексации и базы данных.
Для больших архивов экспортируйте меньший период в Telegram Desktop.
Поиск и чтение в GUI выполняются в фоне, на странице отображается до 50 сообщений.

## Медиа и ссылки

PNG/JPEG/WebP показываются через Avalonia, изображение декодируется с шириной 640 пикселей.
Для файла свыше 20 МиБ используется системный предпросмотр.
Кнопка «Открыть вложение» передаёт файл внешнему системному приложению:

- macOS: команда `open`; MP4/MOV/M4V и WAV/MP3/M4A/AIF/AIFF/AAC — штатному QuickTime Player, документы и остальные поддерживаемые форматы — приложению по умолчанию.
- Windows: оболочка открывает файл приложением по умолчанию; командный интерпретатор не используется.
- Linux: `xdg-open`, пакет xdg-utils, графический сеанс и назначенный просмотрщик.

Плеер внутрь Avalonia не встроен. Поддержка контейнера и кодека определяется просмотрщиком:
расширение MP4 само по себе не гарантирует поддержку любого кодека. Для демонстрации подготовлены PNG,
WAV PCM и MP4 H.264. Установка новых плееров для этих примеров на проверенном Mac не понадобилась.
Если просмотрщика нет или системная команда завершилась с ошибкой, окно показывает объяснение.
Успешная передача файла системе не подтверждает декодирование произвольного файла внешним приложением.

Для внешнего открытия поддержаны распространённые расширения изображений (JPG/JPEG, PNG, WebP, GIF,
BMP, TIFF, HEIC/HEIF, AVIF), видео (MP4, MOV, M4V, WebM, MKV, AVI, MPG/MPEG, 3GP),
аудио (WAV, MP3, M4A, AAC, OGG/OGA/Opus, FLAC, AIF/AIFF, AMR), документов
(PDF, TXT, CSV, JSON, MD, RTF, DOCX, XLSX, PPTX, ODT, ODS, ODP).
Это список допустимого открытия, а не список проверенных кодеков.
Другие файлы остаются видны в переписке; программы, скрипты, архивы и неизвестные расширения кнопка не запускает.
Приложение не скачивает медиа, исключённые настройками Telegram Export.

Пути вложений разрешаются только относительно папки экспорта. Абсолютные пути отдельных вложений,
выход через `..` и символические ссылки наружу блокируются.
На macOS/Linux путь передаётся через ArgumentList одним аргументом, без shell-строки;
на Windows — в FileName с системным действием open. Пробелы и кавычки в имени не становятся командами.
Открытие web-ссылки требует нажатия кнопки; разрешены только HTTP и HTTPS.

## Рабочее состояние `.tgnav.json`, версия 1

Это собственный формат проекта, а не Telegram JSON:

```json
{
  "Version": 1,
  "MediaRoot": "export-folder",
  "Archive": { "Name": "Название", "SourceFormat": "Telegram JSON", "Messages": [] },
  "Query": { "Text": "", "Kind": "All", "SenderId": null, "From": null, "To": null },
  "SelectedMessageId": null
}
```

В непустом файле Messages содержит нормализованные сообщения: Id, Date, SenderId, Sender, Text, Kind,
Attachments, Links, Poll, ReplyToId. Вычисляемые строки GUI не сериализуются.
Сохраняются весь текст архива, медиаописания и опросы, текущий применённый фильтр, выбранное сообщение.
Страница вычисляется по выбранному ID. При сохранении введённые фильтры сначала применяются и проверяются.
Произвольный пиксель прокрутки, размер окна и неиспользованная строка быстрого перехода не являются сохраняемыми данными.
Тема/шрифт находятся в отдельном файле настроек.

MediaRoot обычно содержит относительный путь от места файла состояния до папки медиа; он может содержать `..`,
когда состояние сохранено в соседнем каталоге. Если состояние и медиа находятся на разных дисках Windows,
.NET сохраняет абсолютный MediaRoot, поскольку относительного пути между дисками нет; при переносе
выберите новую папку медиа через GUI. Пути отдельных вложений при этом остаются внутри MediaRoot.
Для переносимости перемещайте вместе состояние и экспорт с прежним взаимным расположением.
Если исходный JSON/HTML исчез, тексты из состояния доступны; если исчезли медиа, используйте «Папка медиа».
Открытие состояния не запускает файлы и не открывает ссылки автоматически.

Перед применением проверяются версия, коллекции, порядок дат, уникальность/положительность ID,
допустимость фильтра, существование выбранного ID и корректность опросов и ссылок.
Неизвестная версия и повреждённые данные дают ошибку **до** замены текущего архива.
Сохранение пишет соседний временный файл, делает Flush и атомарно переименовывает его на локальной файловой системе.
Отмена/ошибка до переименования оставляет прежний файл. Гарантии сетевых и облачно синхронизируемых дисков
зависят от их файловой системы; отключение питания посреди операции отдельно не моделировалось.

Состояние содержит тексты переписки: личные файлы состояния не коммитьте.
`.gitignore` исключает `*.tgnav.json`, bin/obj, логи и сборки.

## Пользовательские настройки, версия 1

`preferences.json` в системном `Environment.SpecialFolder.ApplicationData/TelegramChatNavigator`.
Поля: Version=1, Theme=System/Light/Dark, FontSize=12..22 (GUI предлагает 12, 15, 18, 21).
После «Сохранить настройки» они восстанавливаются при следующем запуске.
Повреждённый файл заменяется значениями по умолчанию в памяти, не мешая открыть чат.
Это локальные предпочтения компьютера, а не содержимое работы.

## Экспорт CSV

UTF-8, разделитель запятая, первая строка: `id,date,sender,text,poll,attachments,links`.
Экспортируются все найденные сообщения, включая другие страницы текущего результата.
Строки заключаются в кавычки, кавычки удваиваются; многострочный текст остаётся многострочным полем CSV.
Для строк, начинающихся с символов формулы таблицы, добавляется апостроф.
CSV подходит для анализа результата. Обратный импорт CSV/Excel и восстановление состояния из CSV не реализованы.
